# تست مرحله چهارم: انتخاب کاربر و بازخورد داخلی

## نتیجه بررسی توسعه‌دهنده

- ۱۳۸ تست خودکار پس از آخرین تغییرات پاس شد.
- Ruff و بررسی قالب هر ۴۷ فایل Python پاس شدند.
- db-check واقعی هر سه دیتابیس را OK اعلام کرد؛ نسخه Schema همان 0001 است.
- `.env`، کلیدها و کاربران واقعی برای تست تغییر نکردند؛ ارسال‌ها در تست شبیه‌سازی شدند.
- انتخاب‌گر واقعی کلاینت Telegram و تحویل بین دو حساب، پس از Restart توسط کاربر بررسی می‌شود.
- مرحله ۵ هنوز آغاز نشده است.

## راه‌اندازی

ربات قبلی را با Ctrl+C متوقف کنید و در پوشه پروژه اجرا کنید:

```powershell
uv sync --locked
uv run --locked python -m app.cli db-check
uv run --locked python -m app.main
```

نیازی به تغییر توکن، شناسه مدیر اولیه، کلیدها یا Migration جدید نیست؛ Schema
همچنان 0001 است. `/start` باید پیام مرحله ۴ و دکمه «همکاران داخل گروه» را نشان دهد.
فقط یک فرایند ربات اجرا کنید. این نسخه ارسال واقعی داخلی دارد، ولی تا پایان
مراحل آزمون نهایی، برای تست از متن و حساب‌های آزمایشی استفاده کنید.

## انتخاب مخاطب بدون تایپ شناسه

پنل مدیریت ← کاربران ← افزودن کاربر. یک دکمه پایین صفحه با عنوان «انتخاب کاربر
تلگرام» نمایش داده می‌شود. آن را بزنید، شخص را در انتخاب‌گر Telegram انتخاب و
نام را در پیش‌نمایش تأیید کنید. شناسه واقعی انتخاب‌شده در users.telegram_id
ذخیره می‌شود؛ نیازی به یافتن یا تایپ آن نیست.

اگر نام از Telegram دریافت نشود یا نام برای ثبت معتبر نباشد، فقط نام نمایشی
پرسیده می‌شود. مدیر بعداً می‌تواند نام سازمانی فرد را از «اصلاح نام» تغییر دهد.
افزودن/تغییر نقش مدیر نیز همین انتخاب‌گر را دارد؛ شخص باید قبلاً به‌عنوان کاربر
فعال ثبت شده باشد. انتخاب شخص به‌تنهایی مجوز مدیریتی نمی‌دهد؛ نقش باید تأیید شود.

این انتخاب‌گر رسمی Telegram است؛ فهرست مخاطبین به ربات ارسال نمی‌شود. فقط
شناسه و نام کاربر انتخاب‌شده دریافت می‌شود. شماره تلفن، عکس و username درخواست
نمی‌شوند. این دکمه از نوع Reply Keyboard است چون Telegram انتخاب کاربر را در
Inline Keyboard ارائه نمی‌کند. سایر عملیات همچنان دکمه‌های درون پیام دارند.
از نسخه به‌روز Telegram استفاده کنید؛ ظاهر فهرست به کلاینت وابسته است و لزوماً
فقط مخاطبین ذخیره‌شده تلفن را نشان نمی‌دهد.

منبع قابلیت و محدودیت‌ها: [Telegram KeyboardButtonRequestUsers](https://core.telegram.org/bots/api#keyboardbuttonrequestusers).

## ارسال بازخورد داخلی

۱. با حساب مدیر، دو حساب آزمایشی A و B را از انتخاب‌گر ثبت کنید.

۲. هر دو حساب یک‌بار در گفتگوی خصوصی ربات `/start` بفرستند. ثبت شخص از مخاطبین
به‌تنهایی اجازه پیام‌رسانی Bot به او نمی‌دهد. اگر گیرنده هنوز Start نکرده باشد،
ارسال پیش از دریافت متن رد می‌شود.

۳. از حساب A: همکاران داخل گروه ← B ← انتقاد یا پیشنهاد ← متن ← ✅ ارسال.
قبل از تأیید، گیرنده، نوع و متن کامل باید نمایش داده شوند. A نباید خودش را
در فهرست ببیند. فهرست صفحه‌بندی و جستجوی نام دارد و افراد غیرفعال را نشان نمی‌دهد.

۴. B باید پیام تازه‌ای از Bot با عنوان «بازخورد ناشناس»، نوع و متن دریافت کند.
نام، username، شناسه A و Forwarded from نباید در قالب پیام باشند. ربات متادیتای
ورودی یا entityهای آن را کپی نمی‌کند. متنی که خود نویسنده هویتش را در آن بنویسد،
به‌صورت خودکار ناشناس‌سازی معنایی نمی‌شود؛ در پیش‌نمایش به این نکته اشاره شده است.

۵. در حساب A، «وضعیت تحویل» را بزنید. ثبت‌شدن در صف با تحویل به Telegram فرق
دارد و تحویل به Telegram به معنی خوانده‌شدن توسط گیرنده نیست. این دکمه به
همان حساب وابسته است و تا ۱۰ دقیقه اعتبار دارد؛ بررسی مجدد توکن تازه می‌دهد.
شروع جریان تازه یا `/start` توکن‌های قبلی همان حساب را باطل می‌کند؛ تاریخچه
پایدار کاربران در مرحله ۶ اضافه می‌شود.

۶. تأیید را دوباره بزنید؛ نباید رکورد یا ارسال دوم ایجاد شود. لغو باید پیش‌نویس
را حذف کند و دکمه تأیید قدیمی دیگر کار نکند. حداقل ۵ نویسه معنادار و حداکثر
۳۰۰۰ واحد UTF-16 پذیرفته می‌شود؛ ایموجی ممکن است دو واحد حساب شود.

۷. در مرحله نوشتن، عکس، فایل یا صدا بفرستید؛ باید رد شود و امکان نوشتن متن باقی
بماند. پیام خارج از این جریان، بدون انتخاب گیرنده ثبت نمی‌شود.

۸. قبل از تأیید، ربات را متوقف و دوباره اجرا کنید؛ بدون زدن `/start` همان دکمه
تأیید را بزنید. تا پایان مهلت ۱۰ دقیقه باید کار کند. `/start` عمداً شروع تازه
است و پیش‌نویس قبلی را لغو می‌کند.

## تحویل و خطا

پیام و صف تحویل در یک تراکنش ذخیره می‌شوند. صف pending بعد از Restart ادامه
می‌یابد. وضعیت فعال‌بودن هر دو طرف، پیش از تحویل دوباره بررسی می‌شود؛ پیام
توقف‌یافته بعد از فعال‌کردن کاربر، خودکار ارسال نمی‌شود. پیامی که درخواست ارسالش
قبلاً در شبکه آغاز شده باشد، با غیرفعال‌سازی هم‌زمان قابل پس‌گرفتن نیست.

در پاسخ RetryAfter، ربات صبر می‌کند و سپس تلاش می‌کند. در قطع شبکه، خطای مبهم
سرور یا قطع فرایند وسط ارسال، نتیجه ممکن است نامشخص باشد؛ ربات برای پرهیز از
ارسال تکراری آن را خودکار تکرار نمی‌کند. وضعیت sending باقی‌مانده پس از انقضای
مهلت ۱۲۰ ثانیه به uncertain تبدیل می‌شود. خطای مسدودکردن Bot وضعیت تحویل را
ناموفق می‌کند؛ عضویت سازمانی شخص را غیرفعال نمی‌کند.

سهمیه تعداد بازخورد وجود ندارد؛ فاصله فنی ارسال‌ها و پاسخ به محدودیت Telegram
برای حفاظت از سرویس است. محتوای دریافت‌شده با protect_content ارسال می‌شود؛
این گزینه تضمین جلوگیری از عکس‌گرفتن یا نقل متن توسط گیرنده نیست.

## تست خودکار

```powershell
uv run --locked pytest -q
uv run --locked ruff check .
uv run --locked ruff format --check .
```

تست‌ها از دیتابیس موقت و Telegram شبیه‌سازی‌شده استفاده می‌کنند و بازخوردی به
حساب‌های واقعی نمی‌فرستند. سناریوهای نامعتبر/منقضی/دزدیده‌شده‌بودن انتخاب کاربر
یا callback، ارسال به خود، تغییر وضعیت کاربر بین پیش‌نمایش و تأیید، Rollback
بعد از درج Outbox، تکرار تأیید، خرابی شبکه و عدم افشای هویت در پیام خروجی تست می‌شوند.

بخش خارجی در مرحله ۵، پاسخ و تاریخچه در مرحله ۶ و گزارش تخلف در مرحله ۷ فعال
می‌شوند؛ این دکمه‌ها در نسخه فعلی ارائه نشده‌اند.
